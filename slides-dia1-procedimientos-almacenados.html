Procedimientos Almacenados

Encapsular lógica de negocio directamente en PostgreSQL para automatizar procesos y garantizar consistencia.

🤔

Escenario

Un cliente hace un pedido en tu tienda online. Necesitas: verificar stock, descontar inventario, registrar la venta y actualizar estadísticas.

¿Enviarías 4 queries separadas desde tu backend?

Concepto

¿Qué es un Stored Procedure?

Un bloque de código SQL que se guarda en el servidor, se compila una vez y se puede ejecutar múltiples veces.

📝 CREATE PROCEDURE
→
💾 Se almacena en pg_proc
→
⚡ CALL para ejecutar
→
🔄 Reutilizable

Disponible desde PostgreSQL 11. Antes de PG 11, solo existían funciones.

¿Cuándo usar procedimientos vs lógica en la app?

✅ Usar procedimiento

  • Lógica transaccional (varias tablas)
  • Consistencia independiente del cliente
  • Múltiples apps acceden a la misma BD
  • Reducir tráfico de red

💻 Mantener en la app

  • Lógica que depende de APIs externas
  • Cambios frecuentes de reglas de negocio
  • Se necesita testing unitario granular
  • El equipo no domina SQL avanzado

⚠️ La decisión siempre es contextual — no hay dogma aquí.

Código en vivo

Primer procedimiento: sin parámetros

CREATE OR REPLACE PROCEDURE aumentar_precios_10()
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE productos
    SET precio = precio * 1.10
    WHERE activo = TRUE;

    RAISE NOTICE 'Precios actualizados correctamente';
END;
$$;

-- Ejecutar
CALL aumentar_precios_10();
Parámetros

Parámetros IN

CREATE OR REPLACE PROCEDURE registrar_producto(
    p_nombre VARCHAR,
    p_precio DECIMAL,
    p_stock  INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO productos (nombre, precio, stock)
    VALUES (p_nombre, p_precio, p_stock);

    RAISE NOTICE 'Producto "%" registrado', p_nombre;
END;
$$;

-- Uso
CALL registrar_producto('Webcam HD', 180000, 20);

💡 Convención: prefijo p_ para parámetros, v_ para variables locales

Parámetros

Parámetros INOUT

CREATE OR REPLACE PROCEDURE calcular_total_inventario(
    INOUT total_valor DECIMAL DEFAULT 0
)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT SUM(precio * stock) INTO total_valor
    FROM productos
    WHERE activo = TRUE;
END;
$$;

-- Devuelve el valor calculado
CALL calcular_total_inventario();

⚠️ Importante

  • Los procedimientos NO tienen RETURN como las funciones
  • INOUT es la forma de "devolver" datos desde un procedimiento
Caso práctico

Caso: Procesar una venta

Somos el equipo de backend de una tienda de tecnología. Necesitamos un procedimiento que procese una venta completa.
1. Recibir producto y cantidad
→
2. Verificar stock
→
3. Descontar inventario
→
4. Registrar venta
Solución

procesar_venta — Completo

CREATE OR REPLACE PROCEDURE procesar_venta(
    p_producto_id INT, p_cantidad INT
)
LANGUAGE plpgsql AS $$
DECLARE
    v_stock INT; v_precio DECIMAL; v_total DECIMAL;
BEGIN
    SELECT stock, precio INTO v_stock, v_precio
    FROM productos WHERE id = p_producto_id AND activo = TRUE;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Producto % no encontrado', p_producto_id;
    END IF;

    IF v_stock < p_cantidad THEN
        RAISE EXCEPTION 'Stock insuficiente: % disponible', v_stock;
    END IF;

    v_total := v_precio * p_cantidad;
    UPDATE productos SET stock = stock - p_cantidad WHERE id = p_producto_id;
    INSERT INTO ventas (producto_id, cantidad, total)
    VALUES (p_producto_id, p_cantidad, v_total);

    RAISE NOTICE 'Venta: % uds por $%', p_cantidad, v_total;
END; $$;
Testing

Probando el procedimiento

-- ✅ Venta exitosa
CALL procesar_venta(1, 2);   -- 2 laptops

-- Verificar resultados
SELECT * FROM ventas;
SELECT nombre, stock FROM productos WHERE id = 1;

-- ❌ Error: stock insuficiente
CALL procesar_venta(4, 50);  -- Solo hay 10 monitores

-- ❌ Error: producto no existe
CALL procesar_venta(999, 1);

Éxito esperado

  • Stock se reduce de 15 a 13
  • Nueva fila en tabla ventas

Error esperado

  • EXCEPTION detiene la ejecución
  • Ningún dato se modifica

Cierre

Recapitulación

  • ✅ Un procedimiento encapsula lógica SQL reutilizable en el motor
  • ✅ Se ejecuta con CALL
  • ✅ Parámetros IN (entrada) e INOUT (entrada/salida)
  • ✅ RAISE para mensajes y errores
  • ✅ DECLARE + SELECT INTO para variables
