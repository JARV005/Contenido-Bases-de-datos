Procedimientos Avanzados

Variables, condicionales, ciclos, manejo de errores y transacciones en PL/pgSQL.

Variables

Declaración de variables

DECLARE
    v_nombre    VARCHAR(100) := 'Sin nombre';    -- valor inicial
    v_precio    DECIMAL(10,2);
    v_cantidad  INT DEFAULT 0;
    v_activo    BOOLEAN := TRUE;

    -- Tipo referenciado (copia el tipo de la columna)
    v_prod_nombre  productos.nombre%TYPE;

    -- Fila completa
    v_producto     productos%ROWTYPE;

    -- Constante
    C_IVA CONSTANT DECIMAL := 0.19;
%TYPE → si cambia la columna, tu código sigue funcionando
%ROWTYPE → accede con variable.columna
Condicionales

IF / ELSIF / ELSE

IF v_precio > 1000000 THEN
    v_categoria := 'PREMIUM';
ELSIF v_precio > 300000 THEN
    v_categoria := 'ESTÁNDAR';
ELSIF v_precio > 50000 THEN
    v_categoria := 'ECONÓMICO';
ELSE
    v_categoria := 'BÁSICO';
END IF;

⚠️ Ojo con la sintaxis

  • Es ELSIF, no ELSE IF ni ELSEIF
  • Siempre cierra con END IF; (con punto y coma)
Condicionales

CASE expression

v_estado := CASE
    WHEN v_stock = 0  THEN 'SIN STOCK'
    WHEN v_stock < 10 THEN 'STOCK BAJO'
    WHEN v_stock < 30 THEN 'STOCK NORMAL'
    ELSE 'STOCK ALTO'
END;

Ideal cuando se asigna un valor basado en múltiples condiciones. Más limpio que múltiples IF para este patrón.

Ciclos

Tipos de ciclos en PL/pgSQL

LOOP

  • Ciclo infinito
  • Sale con EXIT WHEN
  • Control manual

FOR

  • Numérico: FOR i IN 1..10
  • Sobre query: FOR rec IN SELECT...
  • El más usado

WHILE

  • Mientras condición sea TRUE
  • Evalúa antes de cada vuelta
  • Ideal para convergencia
Ciclos

FOR sobre query — el más útil

DECLARE
    v_registro RECORD;
    v_total    DECIMAL := 0;
BEGIN
    FOR v_registro IN
        SELECT nombre, precio, stock, (precio * stock) AS valor
        FROM productos
        WHERE activo = TRUE
        ORDER BY valor DESC
    LOOP
        RAISE NOTICE '%: $%',
            v_registro.nombre, v_registro.valor;
        v_total := v_total + v_registro.valor;
    END LOOP;

    RAISE NOTICE 'TOTAL: $%', v_total;

💡 RECORD se adapta automáticamente a cualquier estructura de query

Errores

Manejo de errores

BEGIN
    -- Código que puede fallar
    SELECT stock INTO STRICT v_stock
    FROM productos WHERE id = p_id;

    -- Lanzar error personalizado
    IF v_stock < p_cantidad THEN
        RAISE EXCEPTION 'Stock insuficiente'
            USING ERRCODE = 'P0001',
                  HINT = 'Disponible: ' || v_stock;
    END IF;

EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE NOTICE 'No existe';
    WHEN SQLSTATE 'P0001' THEN
        RAISE NOTICE '%', SQLERRM;
    WHEN OTHERS THEN
        RAISE NOTICE 'Error: %', SQLERRM;
END;

Transacciones

ACID: Todo o nada

Atomicity

  • Todas las operaciones se aplican, o ninguna

Consistency

  • De un estado válido a otro estado válido

Isolation

  • Las transacciones no se interfieren entre sí

Durability

  • Una vez confirmado (COMMIT), persiste aunque falle el servidor
Transacciones

COMMIT y ROLLBACK

CREATE OR REPLACE PROCEDURE transferencia(
    p_origen INT, p_destino INT, p_monto DECIMAL
)
LANGUAGE plpgsql AS $$
BEGIN
    -- Debitar
    UPDATE cuentas SET saldo = saldo - p_monto
    WHERE id = p_origen;
    -- Acreditar
    UPDATE cuentas SET saldo = saldo + p_monto
    WHERE id = p_destino;

    COMMIT;
    RAISE NOTICE '✅ Transferencia completada';

EXCEPTION WHEN OTHERS THEN
    ROLLBACK;
    RAISE NOTICE '❌ Error: %', SQLERRM;
END; $$;

🔑 Diferencia clave

  • COMMIT / ROLLBACK solo funciona en PROCEDURE
  • Las FUNCTION NO pueden controlar transacciones
